# ЛР4: наглядный сеанс Vivado

Дополнение к [описанию Lab4](../README.md) показывает один вход `SW=03B8` и
основную программу default32. Полная самопроверка выполняется отдельно.

## Подготовить отдельный проект

Откройте свежую Vivado 2023.1 без другого проекта и выполните в **Tcl Console**:

```tcl
source {/path/to/mpsu/Lab4_CYBERcobra/walkthrough/setup_gui.tcl}
```

Замените путь на свой, сохранив фигурные скобки для путей с пробелами.
Файлы `setup_gui.tcl`, `wave_demo.tcl`, `tb_lab4_demo.sv` лежат в `walkthrough`,
а модули, `program.mem` и `board files` — в родительской `Lab4_CYBERcobra`.
Скрипт сам находит эту плоскую структуру. Для иного расположения исходников можно
перед `source` задать:

```tcl
set ::lab4_walkthrough_source_root {/path/to/folder/with/CYBERcobra.sv}
```

Помощник проверяет входные файлы, создаёт новый уникальный
`walkthrough/gui_build/demo_…`, копирует туда `program.mem` и создаёт проект для
`xc7a100tcsg324-1`. Старые проекты не заменяются. Он выставляет аппаратный top
**`nexys_CYBERcobra`**, simulation top **`tb_lab4_demo`** и runtime **0 ns**.
Симуляция, синтез и сборка сами не запускаются. Путь проекта выводится строкой
`WALKTHROUGH_PROJECT`, путь скрипта волн — `WALKTHROUGH_WAVE_SCRIPT`.
Переменная `wave_script` остаётся в Tcl Console.

## Пройти экраны по порядку

1. **Sources → Design Sources**: найдите `nexys_CYBERcobra` и его `dut: CYBERcobra`.
   Пакеты и модули ЛР1–ЛР3 уже добавлены. В **Simulation Sources** top — `tb_lab4_demo`.
2. **Run Simulation → Run Behavioral Simulation**. Модель загрузится на времени
   **0 ns**; программа ещё не исполнялась.
3. В Tcl Console выполните:

   ```tcl
   source $wave_script
   ```

   Скрипт создаёт конфигурацию волн с группами и нужными системами счисления.
   Сам он время не запускает. Если переменная потеряна, укажите свой путь:

   ```tcl
   source {/path/to/mpsu/Lab4_CYBERcobra/walkthrough/wave_demo.tcl}
   ```

4. Введите **100 ns** в поле интервала и нажмите **Run For**. Сначала идут два
   фронта синхронного HIGH-сброса, затем обычные фронты на 50, 70, 90, … ns.
   `ordinary_step` показывает число уже выполненных обычных фронтов.
5. Нажмите **Run All**, затем **Zoom Fit**. Ожидаются `test_pass=1`,
   `pc=0000002C`, `out=00000014` и строка:

   ```text
   DEMO_PASS SW=03B8 OUT=00000014 PC=0000002C after 35 ordinary steps; J0 stable for 2 extra steps; checks=43
   ```

   Завершение `$finish` — в **850 ns**. Это демонстрация одного входа, а не полный перебор.
6. **Close Simulation → RTL Analysis → Open Elaborated Design**. Раскройте
   `dut: CYBERcobra` и откройте **Schematic**. Покажите путь данных и обратную
   связь PC до перехода к оптимизированной схеме после синтеза.
7. Для платы top остаётся **`nexys_CYBERcobra`**: **Run Synthesis → Run Implementation →
   Generate Bitstream**. Используйте XDC этой лабы; чип — `xc7a100tcsg324-1`.

`build_sim.tcl` и `build_bitstream.tcl` запускаются в отдельном Vivado batch из
терминала, как в [основном README](../README.md). Не выполняйте их через `source`
в этом GUI-сеансе: они предназначены для собственных отдельных проектов.

## Что объяснять на схеме и волнах

Путь данных: **PC → ROM инструкций → регистровый файл → АЛУ → мультиплексор
записи → регистровый файл**. Поля инструкции управляют выбором регистров и операций.
Обратная связь PC выбирает `+4` или знаковое смещение перехода ×4.

Есть ROM инструкций 512 байт (128×32) и RF 32×32 с двумя портами чтения и одним
портом записи. **Отдельной памяти данных с load/store пока нет.** `RA1/RA2` — адреса,
`rd1/rd2` — числа; `WA` — адрес назначения, `write_data` — записываемое число,
`we` — разрешение записи. Переходы запрещают запись в RF.

Сброс синхронный, активный HIGH; он сбрасывает PC на положительном фронте.
RF не имеет reset, его начальные значения задаёт программа. На фронте записываются
данные команды, видимой **до фронта**; после обновления PC видны уже поля следующей.
`out=rd1`, поэтому в цикле выход меняется вместе с `RA1`; постоянный `r1` виден
на конечном `J 0`.

Контрольные точки после снятия reset:

- шаг 5: `pc=14`, начальные регистры заданы;
- шаги 11, 17, 23, 29: возврат на `pc=14`; `r2=EE,3B,E,3`, `r1=0,0,4,4`;
- шаг 35: `pc=2C`, `r2=0`, `r1=14`, `out=14`;
- следующие два шага удерживают результат.

PC и значения регистров здесь записаны в HEX, номера шагов — в десятичной системе.
Алиасы волн находятся в TB; у ядра не добавлено портов.

## Границы проверки

Этот TB локально прошёл **43 проверки в Icarus**, завершившись в 850 ns.
Фактический сеанс Vivado GUI с этими помощниками пока не проверен. Ранее записанные
полные результаты Vivado/XSim для основного RTL и двух программ описаны
[в README](../README.md); они не означают проверку нового GUI-сеанса.
Генерация `.bit` не подтверждает работу на плате: физическая плата/JTAG, полная
timing-валидация CPU и электрическая конфигурация остаются непроверенными.
