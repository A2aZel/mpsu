# ЛР4: наглядный сеанс Vivado

Дополнение к [описанию Lab4](../README.md) показывает основную программу
default32 на одном выбранном 16-битном входе. По умолчанию это `SW=03B8`;
для другого числа достаточно изменить `sw` в том же `tb_lab4_demo.sv`.
Ожидаемый результат и контрольные точки вычисляются автоматически.
Полная самопроверка с перебором входов выполняется отдельно.

## Подготовить отдельный проект

Откройте свежую Vivado 2023.1 без другого проекта и выполните в **Tcl Console**:

```tcl
source {/path/to/mpsu/Lab4_CYBERcobra/walkthrough/setup_gui.tcl}
```

Замените путь на свой, сохранив фигурные скобки для путей с пробелами.
Файлы `setup_gui.tcl`, `wave_demo.tcl`, `tb_lab4_demo.sv` лежат в `walkthrough`,
а модули, `program.mem` и `board files` — в родительской `Lab4_CYBERcobra`.
Скрипт сам находит эту плоскую структуру. Для иного расположения исходников можно
перед `source` задать:

```tcl
set ::lab4_walkthrough_source_root {/path/to/folder/with/CYBERcobra.sv}
```

Помощник проверяет входные файлы, создаёт новый уникальный
`walkthrough/gui_build/demo_…`, копирует туда `program.mem` и создаёт проект для
`xc7a100tcsg324-1`. Старые проекты не заменяются. Он выставляет аппаратный top
**`nexys_CYBERcobra`**, simulation top **`tb_lab4_demo`** и runtime **0 ns**.
Симуляция, синтез и сборка сами не запускаются. Путь проекта выводится строкой
`WALKTHROUGH_PROJECT`, путь скрипта волн — `WALKTHROUGH_WAVE_SCRIPT`.
Переменная `wave_script` остаётся в Tcl Console.

## Пройти экраны по порядку

1. **Sources → Design Sources**: найдите `nexys_CYBERcobra` и его `dut: CYBERcobra`.
   Пакеты и модули ЛР1–ЛР3 уже добавлены. В **Simulation Sources** top — `tb_lab4_demo`.
2. **Run Simulation → Run Behavioral Simulation**. Модель загрузится на времени
   **0 ns**; программа ещё не исполнялась.
3. В Tcl Console выполните:

   ```tcl
   source $wave_script
   ```

   Скрипт создаёт конфигурацию волн с группами и нужными системами счисления.
   Сам он время не запускает. Если переменная потеряна, укажите свой путь:

   ```tcl
   source {/path/to/mpsu/Lab4_CYBERcobra/walkthrough/wave_demo.tcl}
   ```

4. Введите **100 ns** в поле интервала и нажмите **Run For**. Сначала идут два
   фронта синхронного HIGH-сброса, затем обычные фронты на 50, 70, 90, … ns.
   `ordinary_step` показывает число уже выполненных обычных фронтов.
5. Нажмите **Run All**, затем **Zoom Fit**. Для исходного `03B8` ожидаются `test_pass=1`,
   `pc=0000002C`, `out=00000014` и строка:

   ```text
   DEMO_PASS SW=03B8 OUT=00000014 PC=0000002C after 35 ordinary steps; J0 stable for 2 extra steps; checks=43
   ```

   Завершение `$finish` для `03B8` — в **850 ns**. При другом входе время
   зависит от числа итераций, но не превышает **2170 ns**. Это проверка
   выбранного входа, а не полный перебор.
6. **Close Simulation → RTL Analysis → Open Elaborated Design**. Раскройте
   `dut: CYBERcobra` и откройте **Schematic**. Покажите путь данных и обратную
   связь PC до перехода к оптимизированной схеме после синтеза.
7. Для платы top остаётся **`nexys_CYBERcobra`**: **Run Synthesis → Run Implementation →
   Generate Bitstream**. Используйте XDC этой лабы; чип — `xc7a100tcsg324-1`.

`build_sim.tcl` и `build_bitstream.tcl` запускаются в отдельном Vivado batch из
терминала, как в [основном README](../README.md). Не выполняйте их через `source`
в этом GUI-сеансе: они предназначены для собственных отдельных проектов.

## Изменить вход в Windows / Vivado

1. В **Sources → Simulation Sources** дважды щёлкните `tb_lab4_demo`, чтобы
   открыть `tb_lab4_demo.sv`.
2. В начале файла найдите строку:

   ```systemverilog
   logic [15:0] sw = 16'h03b8;
   ```

   Замените только `03b8`, например на `0055`. `16'h` означает 16-битное число
   в шестнадцатеричной записи; допустимый диапазон — `0000`…`FFFF`.
3. Нажмите **Ctrl+S**, затем **Relaunch Simulation**. Обычный **Restart**
   сбрасывает время уже скомпилированной модели и не подхватывает правки файла.
4. При необходимости снова выполните `source $wave_script` в Tcl Console.
   Нажмите **Run All → Zoom Fit** и установите курсор в конце диаграммы.
5. Проверьте `test_pass=1`, `pc=0000002C`, результат `out` и строку `DEMO_PASS`
   в Tcl Console. Ожидаемые значения внутри тестбенча менять не нужно.

Примеры для программы default32:

| Вход `sw` (HEX) | Конечный `out` (HEX) | Рабочих шагов |
|---|---|---:|
| `0000` | `00000000` | 11 |
| `0001` | `00000001` | 11 |
| `0002` | `00000000` | 11 |
| `0055` | `0000000F` | 29 |
| `03B8` | `00000014` | 35 |
| `5555` | `000000FF` | 53 |
| `8000` | `0000FF00` | 101 |
| `FFFF` | `0000FFFF` | 101 |

Вход сначала **знаково расширяется с 16 до 32 бит**, затем программа собирает
биты с чётными номерами. Поэтому `8000` превращается в `FFFF8000`, а его
результат — `0000FF00`. Это поведение исходного процессора и программы.

Для автоматических прогонов из командной строки тот же TB также принимает
необязательный аргумент симулятора `+SW=0055` (HEX). Он переопределяет значение
из строки `sw` только на этот запуск. Например, после компиляции Icarus:

```sh
vvp /path/to/tb_lab4_demo.vvp +SW=0055
```

Для обычной работы в GUI используйте редактирование строки и **Relaunch
Simulation** — отдельный режим или другой тестбенч не нужны.

## Что объяснять на схеме и волнах

Путь данных: **PC → ROM инструкций → регистровый файл → АЛУ → мультиплексор
записи → регистровый файл**. Поля инструкции управляют выбором регистров и операций.
Обратная связь PC выбирает `+4` или знаковое смещение перехода ×4.

Есть ROM инструкций 512 байт (128×32) и RF 32×32 с двумя портами чтения и одним
портом записи. **Отдельной памяти данных с load/store пока нет.** `RA1/RA2` — адреса,
`rd1/rd2` — числа; `WA` — адрес назначения, `write_data` — записываемое число,
`we` — разрешение записи. Переходы запрещают запись в RF.

Сброс синхронный, активный HIGH; он сбрасывает PC на положительном фронте.
RF не имеет reset, его начальные значения задаёт программа. На фронте записываются
данные команды, видимой **до фронта**; после обновления PC видны уже поля следующей.
`out=rd1`, поэтому в цикле выход меняется вместе с `RA1`; постоянный `r1` виден
на конечном `J 0`.

Для входа `03B8` контрольные точки после снятия reset:

- шаг 5: `pc=14`, начальные регистры заданы;
- шаги 11, 17, 23, 29: возврат на `pc=14`; `r2=EE,3B,E,3`, `r1=0,0,4,4`;
- шаг 35: `pc=2C`, `r2=0`, `r1=14`, `out=14`;
- следующие два шага удерживают результат.

PC и значения регистров здесь записаны в HEX, номера шагов — в десятичной системе.
Для другого входа TB сам вычисляет ожидаемый результат (`expected_result`)
по чётным битам исходного знакорасширенного числа, независимо от регистров DUT.
Частичные результаты, остаток `r2`, позиция `r4` и выбранный бит `r6`
проверяются после каждой шестикомандной итерации. Последний шаг имеет номер
`5 + 6 × число_итераций`: от 11 до 101. После него ещё два шага проверяют,
что конечный `J 0` удерживает PC и выход. Для `03B8` остаются 35 рабочих
шагов и 43 проверки.

После `test_pass=1` генератор тактов останавливается. Watchdog на 3000 ns
выдаёт ошибку только при незавершённом тесте: повторный **Run All** после
успешного `$finish` не должен создавать ложный `DEMO_FAIL watchdog expired`.
Алиасы волн находятся в TB; код ядра и программа не изменены, новых портов нет.

## Границы проверки

11 ноября 2026 года изменённый TB проверен в **Icarus Verilog 13.0**:
24 разных входа, включая ноль, каждый отдельный бит, `0055`, `03B8`,
`8000` и `FFFF`. Проверены также изменение только строки `sw`, обнаружение
повреждённой программы и продолжение после `$finish` без ложного watchdog
или бесконечного генератора тактов. Все 12 методов Python-тестов прошли:
8 тестов конвертера и 4 теста демонстрации. Для `03B8` подтверждены прежние
**35 рабочих шагов, 43 проверки и завершение в 850 ns**.

Тесты находятся в `tests/test_lab4_demo.py`; запуск из `Lab4_CYBERcobra`:

```sh
python3 -m unittest discover -s tests -v
```

Для RTL-проверок нужны `iverilog` и `vvp` в `PATH`; без них четыре теста
демонстрации помечаются как пропущенные, а тесты конвертера продолжают работать.
Ранее записанные полные результаты Vivado/XSim для основного RTL и двух программ
описаны [в README](../README.md); новая версия TB в Vivado/XSim здесь не запускалась.
Генерация `.bit` не подтверждает работу на плате: физическая плата/JTAG, полная
timing-валидация CPU и электрическая конфигурация остаются непроверенными.
